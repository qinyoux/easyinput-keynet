# EasyInput KeyNet — 办公键盘变形记：零固件改动的智能家居中控

> WaytoAGI AI 硬件训练营 · 第 8 课大作业
> **一块办公键盘，一行固件不改，在 PC 软件里长成生活中控面板。**

把一台 EasyInput V2.0（ESP32-S3 开发板）插上电脑，按一个键，你家的灯、风扇、插座、温控就动了——
中间经过一台新写的 PC 应用（Companion）和一块 ART-Pi（RT-Thread）中控主机。

## 三个"不按套路"的设计决策

**1. 固件零改动。** ESP32-S3 跑社区固件原样，一个字节没烧。按键事件以 Host Action UUID 经 USB HID 上报（该通道社区固件已实机验证 7/7）。
所有新形态——场景状态机、协议桥、可视化——全部长在 PC 侧的 Companion 里。这正是第 8 课"硬件固定后靠软件迭代"的实证。

**2. 为什么不走 WiFi/蓝牙直连 PC？**（被问得最多的问题）
- **WiFi**：已被固件的语音链路独占（TCP :17333，带租约/深睡协调）。板子再当 UDP 客户端 = 改固件 + 抢 STA 租约，深水区。
- **蓝牙**：固件确实有 BLE HID 组件，但它是标准 HID over GATT 键盘角色，不承载自定义报文；复用要改 report map，还是动固件。
- **USB HID**：固件已实现、真机验证过、PC 侧有成熟轮子。在"零改动 + 快速交付"约束下，它是唯一全过的通道。无线化是完整版（固件直连）的升级方向，协议资产已在 Companion 里备好。

**3. 重传必须换 seq（最隐蔽的坑）。** ART-Pi 用 16 槽位图给收到的帧去重，PC 侧重传若沿用旧 seq，会被当成重放直接吃掉——现象是"日志显示发了、板子就是不动"。Companion 每次重传都申请新 seq，并有单测钉死这条语义。

## 三分钟跑起来

**路线 A：只有 PC（无任何硬件）** — 用协议模拟器体验 PC 侧闭环：

```bash
# 终端 1：起 ART-Pi 协议模拟器（复刻 V2.3：CRC/去重/Ack/状态帧）
python artpi-sim/artpi_sim.py

# 终端 2：起 Companion（Tauri 2）
cd companion && npm install && npm run tauri dev
# Config 面板把 ART-Pi IP 填 127.0.0.1 —— 链路灯变绿即可用命令注入台发命令
```

**路线 B：完整三实体** — EasyInput 板（USB）＋ ART-Pi（局域网）＋ 本仓库 Companion：

1. `cd companion && npm install && npm run tauri dev`
2. 板的按键 UUID 用配置工具（easyop 或直接改 NVS）分配为本工程保留段：
   场景 `…0101–0108` / 设备直控 `…0201–0206` / 编码器 `…0301–0303`
3. Companion Config 面板填 ART-Pi 实测 IP（默认模板值是 192.168.1.10，**别忘改**）
4. 按键 → Companion 日志 → ART-Pi 执行 → 状态帧回传，全链路可感知

**路线 C：只读代码与设计** — `第8课大作业规划.md`（V2.1，含路线 D/E 评估、协议契约、风险表）。

## 已知边界（诚实清单）

- ART-Pi 的 `on_scene`（0x47 本地展开）在真源里是 TODO(M4) 桩，故 Companion 默认在 PC 侧展开场景；`scene_mode="remote"` 已预留切换位
- 0x16 灯效下行通道固件侧未实板验证，本工程降级为 PC 界面反馈
- 演示依赖 PC 不休眠（USB HID 链路的结构性取舍，脚本内有 Checklist）
- 模拟器与真源差异仅限仿真便利（温控一阶趋近 vs PID），协议语义一致
